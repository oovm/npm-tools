# v0.1.12

Align ref handling across the CLI, and make CI prove its own coverage.

## Changes

- `nifty-types::RefError` owns the wording for a missing ref and for a ref that does not peel to a commit, shared by
  `check`, `lint`, and `change-logs`
- Report the unpeeled object kind (`tag`, `tree`, …) from both the gix and git CLI backends instead of dropping it
- Keep `--version` failures phrased as `release tag …` through a `RefDomain` label while reusing `verify_commit_ref`
- Ambiguous short hashes still print `Candidates are:` on gix, and the git CLI limitation stays a recorded backend
  difference
- `resolveRange` matches `change-logs`: bare versions map to `vX.Y.Z`, other refs stay verbatim, annotated tags peel to
  their commit
- `change-logs` accepts git refs in `--to`, orders pre-release tags by semver, reports missing refs clearly, and no longer
  emits `vdev`
- `-C` decides which history `nifty lint` scans and resolves relative `--releases-dir`, author maps, and
  `commit export` / `commit apply` `--path`
- `commit apply` warns when a tag still points at a pre-rewrite commit (it never moves tags)
- `nifty publish` aborts when a native platform package has no staged `.node` instead of shipping a meta package whose
  optional dependency does not exist
- `nifty install-native` requires the full five-platform publish matrix, so a partial artifact tree no longer reports
  "ready for npm publish"
- Native eligibility now comes from the platform package manifest: `main` names the addon, `nifty publish` proves that
  file is in `npm pack --dry-run --json`, and `--dry-run` shares that check with a real publish
- Platform packages publish their Node-API addon as `main` (`lib/index.<target>.node`) instead of an `index.js` wrapper
  that scanned `lib`
- `nifty install-native` and `build:napi` stage only the addon each manifest declares and drop addons left by earlier
  runs, and the release workflow stages artifacts through `nifty install-native` instead of a second copy layout

## Tooling

- Workspace uses `resolver = "2"`, with a `Cargo.lock` generated in a clean clone rather than through local path patches
- CI and `build:napi` build with `--locked`, and a structural check rejects a lock resolved through local paths
- CI runs every workspace test target with `--no-fail-fast` and asserts that each target emitted a `Running` line, so a
  fail-fast stop can no longer hide unexecuted crates
- `test:ci` reproduces the CI flags locally while the default `test` entry stays usable with the local Oak overlay
- `nifty-napi` and `nifty-types` now ship the `readme.md` that `nifty check` expected, and crate readme examples match
  the real APIs
- The published skill layout lists the actual `scripts/ci` files instead of a removed entry point

## Note

Local `.cargo/config.toml` patches `oak-*` to path sources, which rewrites `Cargo.lock` and can fail formatter tests
against an Oak API newer than the pinned revision. Close the overlay or use a clean clone for a full local run.
